# 目標契約｜guide-1115
凍結：2026-11-15

Cross 原話：
> 現在今日任務的前後順序沒辦法手動排序
> 我想要自定義的輸入欄位也非常難輸入
> 我也不是一定要去art gallery 我只是想去有趣的地方或是景觀好的地方喝咖啡 或是好喝的店喝咖啡 或是特別針對一間好吃的餐廳 或是去漂亮的公園沒去過的區域等等探險
> 你要靈活提供我建議
> 我的目標是建置一個個人生活導遊

目標：今日行程是一個個人生活導遊：站的順序由 Cross 說了算、想去哪裡打字就能輸入、探索建議有多種主題而且會變化。

成功指標（⚠️ Cross 沒給，Fable 代定）：Cross 在手機上能 (1) 用手指調整站的順序，路線照他的順序走；(2) 順利打出中文或日文的自訂地點；(3) 不指定時拿到的探索站不再固定是藝廊，會在多種主題間變化，也能自己選主題。

STOP 條件：
1. 手動排序：每一站可上移／下移（觸控目標 ≥44px，iPhone 寬度可用）。手動排過之後，伺服器照使用者順序排路線並算 ETA，不再重排可移動站；固定行程仍照自己的時間，來不及時照舊警告。有「恢復自動排序」。順序存檔，重開頁面還在；換店、重新生成不打亂。
2. 自訂輸入好打：先在 iPhone 模擬（Chromium＋WebKit）重現問題並寫下根因，再修。必驗：中文／日文輸入法組字中不被打斷、不丟字；打字時不失焦、不跳動；鍵盤不遮住輸入框；Enter 或按鈕能送出；一個地方就能輸入自訂地點。
3. 探索主題：原本固定「藝術展／IP 快閃」的探索站改成有主題的探索站。至少這些主題：景觀好的咖啡、好喝的咖啡、有趣的地方、漂亮的公園、沒去過的區域、值得專程去的餐廳、藝文展覽（保留為其中之一，不是預設唯一）。每站可換主題；有「讓導遊決定」，每次重新生成在主題間變化。
4. 「沒去過的區域」：依本機紀錄（去過、看過的店所在區域）避開去過的區域；沒有紀錄時照常給建議。不發明資料。
5. 靈活建議：每個探索站顯示一行理由（為什麼推這裡，來自真實資料：主題、評分、距離等），不編造。
6. 既有守則不破：不發明店、營業狀態、路線時間；到店要開著；指定站、固定行程、已完成站、單站換店、2.4 偏好、seen／disliked 行為不變；ROADMAP §7.7 守則（不寫自由文字意圖解析器；種類判斷只用 type＋品牌）。
7. `npm run typecheck` 0、`npm run lint` 0、`npm test` 全過、`npm run check:bundle` 過、`npm run build` 過；新行為有單元測試；真瀏覽器（iPhone 模擬）驗證 1–3 有截圖。
8. 預覽站真 POST 驗證：手動順序被伺服器照做；至少 4 個主題各拿到真店；合併後正式站再驗一次。
9. `STATE.md`、`docs/ROADMAP.md`、`.handoff/LATEST.md` 與實況一致。

等級：M（三件事都改同一個前端檔，一條工作線；獨立把關者驗收）
預算：預估 ~550k token，上限 ~800k
保留事項：對外發布（合併 main＝正式站部署）— Cross 既有授權 `merge不用再我批准`、`CI 綠了就合併`、`其他fable代替我核准`。排在把關 PASS 之後。
⚠️ 假設：
- 手動順序優先於「步行最短」。預設：排過就照使用者的；沒排過維持現行自動排法。
- 每個主題多用 Google Places 查詢。預設：每個探索站每次生成只查一個主題，不增加每站查詢次數。
- 產品碼預計超過 300 行（三個功能）。理由：排序、輸入、主題是三個獨立功能，各自最簡。
